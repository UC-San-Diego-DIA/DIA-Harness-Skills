# Separate requirement-first and model-first question catalogs

Business questions appear in two flows that start from opposite sides. `dia-data-model-docs` is model-first: it proposes the questions an existing BI Publisher model can answer, derived from that model's extracted facts. The transcript-to-KPIs flow is requirement-first: it records what stakeholders asked for before any dataset or model exists, and it also captures the KPIs they expect to be built. The vocabulary overlaps, but the direction, inputs, confirmation timing, and consumers differ, so the team keeps them as separate skills.

Merging the two would force one artifact to serve both directions: a model-first catalog must never promise questions the model cannot answer, while a requirement-first catalog must record everything stakeholders asked for even when no current data supports it. `dia-transcript-to-kpis` therefore writes `kpi-facts.yaml` as the contract that `dia-kpi-data-mapping` validates against a user-named dataset, and `dia-data-model-docs` keeps documenting what an existing model supports. Dataset mapping stays in its own skill so the extraction skill never reads data files and the mapping skill never invents definitions.
